# dev-tools

Development tools for Manutencao Conectada.

## Structure

dev-tools/
├── docker-compose.yml
├── .env                        (generated by sonar-setup.sh and beef-setup.sh, not committed)
├── sonar/
│   ├── backend.properties
│   └── frontend.properties
├── scripts/
│   ├── sonar-setup.sh          first-time SonarQube setup
│   ├── sonar-scan.sh           run analysis
│   ├── beef-setup.sh           first-time BeEF setup
│   └── beef-start.sh           start BeEF (after setup)
└── README.md

## SonarQube

### First time

bash dev-tools/scripts/sonar-setup.sh

This will:
1. Start the SonarQube container
2. Change the default admin password
3. Create the backend and frontend projects
4. Generate a token and save it to dev-tools/.env

### Run the scan

bash dev-tools/scripts/sonar-scan.sh

Scans backend and frontend separately. Works on any branch. No need to push to main.

Dashboards:
- http://localhost:9000/dashboard?id=manutencao-conectada-backend
- http://localhost:9000/dashboard?id=manutencao-conectada-frontend

### Stop

cd dev-tools && docker compose down

## BeEF

Local client-side security testing (XSS) against our own application only. Never expose these ports publicly, and never include the hook on a production page.

### First time

bash dev-tools/scripts/beef-setup.sh

This will prompt for a password, save it to dev-tools/.env, start the container and wait until it's ready.

### Run (after setup)

bash dev-tools/scripts/beef-start.sh

- Panel: http://localhost:3000/ui/panel (user: beef)
- Hook (paste on a test page only): http://localhost:6789/hook.js

### Stop

cd dev-tools && docker compose down

## Notes

- Default SonarQube login is admin/admin before setup
- dev-tools/.env holds SONAR_TOKEN and BEEF_PASS; it is never committed
